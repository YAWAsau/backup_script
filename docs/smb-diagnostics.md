# v802 SMB 掃描與功能 8 診斷

本次實機確認：主力機 10.190.6.36 的 SpeedBackup 分享公開手機儲存空間根目錄。備份實際位於 虛擬分區/Backup_zstd_0，因此 SMB 基底需設為 smb://10.190.6.36/SpeedBackup/虛擬分區。功能 8 會自行追加 Backup_zstd_0，不應將該資料夾再填入基底。

已提供的帳密可通過認證及共享列舉。匿名登入不能存取該分享，但使用者目前設定檔已有正確帳密，功能 8 的實際失敗是基底少一層子目錄。舊掃描日誌未保留列舉 stdout，無法回溯當時空清單的唯一原因。

修正：
- 共享列舉先取得 smbclient 原始返回碼，記錄 stdout/stderr，再解析共享；分辨認證拒絕、連線錯誤、逾時及空清單。
- 掃描顯示匿名／已設定帳密模式；不輸出密碼。隱藏分享可顯示，僅在已明確設定時自動選用。
- 已設定分享未出現在列舉結果時，唯讀 tree-connect 確認能否直接連線。
- 自動套用前實際確認分享連線；選到既有分享時保留原本子目錄，不再丟掉 /虛擬分區。
- 功能 8 在錯誤判定前保留完整回覆及返回碼；找不到目錄時顯示目前基底及其下最多 20 個資料夾，說明要設定備份資料夾的上層。
- 目錄查詢非零退出不再當成正常空清單；移除根路徑拼接的重複斜線。實測本次兩種斜線寫法均找不到舊基底，重複斜線不是本次根因。

驗證：備用機 Android mksh + 交付 BusyBox 七組隔離回歸通過；真實主力機帳密列舉、分享直連，以及修正後功能 8 SMB 列目錄分支通過，正確基底讀到 4 個子資料夾。未上傳、刪除、恢復遠端資料；未完整執行功能 8 後續 metadata 清單生成或功能 10 下載。

除錯檔名：remote_smb_scan_raw.log、remote_smb_list_raw.log。交付不含帳密。版本 v802 保留 v801 關機提示相容性修復。

# v803 本地備份透過分享串流恢復

當同一備份根目錄的完整預掃清單確認沒有 app_details_bundle.tar.zst 或 app_details_bundle.tar 時，功能 11 改用所選 App 目錄內的 app_details.json。集中包存在時維持原流程，集中包損壞不退回可能過期的逐 App JSON。清單失敗或來源 context 不符不啟用此路徑。

只下載所選 metadata，沿用 Rust JSON 驗證；缺失、下載失敗、JSON 損壞或必要 metadata 缺失一律中止。全部通過後才發布本輪 staging，失敗不留下部分 staging。Media 使用自己的 JSON key 驗證並去重；系統資料選項維持既有流程。

SMB 預掃新增成功回執，非零返回碼及部分目錄 NT_STATUS 錯誤不再標記為完整清單。冷備份根目錄不存在仍回傳空列表，但不提供完整清單回執。

驗證：Android mksh + 本次交付 Rust/BusyBox，13 組回歸分類通過（含多種路徑與錯誤變體）。真實 SMB 讀到 28 筆檔案，酷安 app_details.json 15,850 bytes 經正式下載 helper 與 Rust metadata 驗證通過。僅測試恢復前 metadata 準備，未執行 App 安裝或資料覆寫；WebDAV 的分支判斷沿用同一程式，未做本輪 WebDAV 真實網路驗證。
