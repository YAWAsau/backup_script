# Google 地圖時間軸備份與恢復

時間軸隨 Google 地圖的既有備份／恢復流程處理，不需另開時間軸選單。地圖備份目錄內的 `timeline_<UUID>.sbtimeline` 由 metadata 引用，本地、WebDAV、SMB 使用相同入口。封存含位置／行程資料與來源帳號顯示名稱，不含 Google 登入權杖、密碼或 Keystore 金鑰。

## 帳號提示

恢復前顯示：

> 此時間軸來自「來源名稱」，將匯入至「目的名稱」的時間軸。

新版備份保存來源名稱。舊備份沒有名稱時，只在來源紀錄 ID 能對應到接收端已登入帳號時顯示該帳號目前名稱，否則顯示「來源帳號名稱未知」。目的名稱從接收端讀取；名稱僅用於顯示，實際使用內部帳號識別核對。

備份自動保存每個有紀錄且可識別的帳號，不要求互動。v902 恢復會先依帳號識別 selector 規劃來源與已登入帳號的配對；顯示名稱不參與授權。只要有同帳號匹配，就只恢復所有匹配帳號，略過未登入的來源：來源 a、b 而裝置只登入 a 時只恢復 a，兩個都登入則都恢復。完全沒有同帳號匹配時，才保留手動選擇目的帳號；即使只有一個候選仍詢問，背景模式則在寫入前停止。最後顯示完成及略過數量。略過的來源仍保留在原始備份，串流模式只清除下載到本機的副本。禁止多個來源覆寫同一目的帳號。目的帳號需已登入並開啟時間軸、建立 Geller 資料庫，但不要求已有行程。

配對規劃先完成，驗證與執行逐帳號進行。每個帳號是獨立交易，途中失敗會顯示已完成數，已完成帳號不整批回滾。串流下載的封存在正常返回的成功與失敗路徑都會清除；SIGKILL 或斷電不保證清理。每次 Java 控制器建立唯一 run 目錄，完成或未進入交易的失敗會清理選取封存；待回滾交易仍保留必要快照。

本版本不更動時間軸／位置記錄與加密雲端備份開關；相關實驗源碼已移除。時間軸資料恢復與登入帳戶配對功能保留。

備份依時間軸紀錄的帳號 ID 選擇來源，不以 Geller 暫存是否非空判定。多帳號快照會在私有副本依帳號過濾，保留各自的行程／編輯內容並重建同步範圍；不改寫手機資料。無法對應到已登入帳號的紀錄會拒絕備份，避免靜默遺漏。

單帳號沿用 format 1 封存；多帳號使用 format 2 外層索引，每個帳號內含獨立 format 1 快照及 SHA。新版同時讀取兩種格式；舊版不能讀多帳號封存。

## 跨裝置／跨帳號

v851 的跨裝置結構比較容許 `semantic_segment_table` 與 `edited_segment_table` 在 `CREATE TABLE` 開頭使用或省略表名雙引號。只處理這兩個已知表名，欄位、約束、索引與觸發器仍逐項比對；原始封存的 schema 雜湊驗證不變。`TimelineUtil check-archive` 可執行同一份匯入前檢查及私有副本轉換，成功後輸出 `TIMELINE_RESTORE_PREFLIGHT_OK`，不進入正式寫入。

恢復只取代所選目的帳號的本機時間軸，保留其他帳號的紀錄；目的帳號原有歷史仍是取代，不是合併。同一份歷史可分別匯入不同帳號。不同帳號時，在私有副本轉換 ODLH／aux 帳號欄位，不移植來源帳號的加密 Geller／同步 payload。

遇到其他帳號佔用相同行程 ID 或來源資料庫／紀錄唯一鍵時，僅對匯入副本分配目的帳號專屬識別；同步改寫已驗證的 semantic protobuf 第 6 欄行程 ID。SQL 本地列 ID 衝突也會重映射，行程內容、日期、來源紀錄 ID 與編輯內容保持不變。重新分配識別時不恢復來源加密 Geller payload。未知的內嵌識別參照會拒絕寫入。交易內逐表核對目的內容及其他帳號完整列，原始封存不改寫。

原始備份不改寫。來源 SHA、SQLite 完整性、資料庫版本和結構均先檢查；跨裝置僅容許 semantic_segment_table.database_id 的裝置專屬預設值不同。副本轉換時在交易內暫時移除更新時間觸發器，完成後原樣重建，避免刷新所有歷史紀錄時間。

## 一致性與中斷保護

v850 支援時間軸已啟用、但 GMS 尚未建立 `aux-odlh-storage.db` 的裝置。使用工作目錄內的私有空表表示缺少的輔助資料庫，不在 GMS 目錄建立檔案。來源輔助表必須為空且符合已支援的結構；若有輔助紀錄，回報 `aux_missing_nonempty_backup` 並在寫入前停止，不能略過資料。凍結後再核對資料庫存在狀態，若期間改變則停止。既有主資料庫／Geller 的版本、結構、帳號及完整性檢查保留。

回滾來源與比較基準為同一份快照時，只掛載一次 Geller 快照，避免 SQLite rollback-journal 模式下重複掛載造成自我鎖定。終端僅在存在 pending 交易時提示保留待修復快照；未進入寫入的檢查失敗不再一律宣稱有回滾快照。

Dex 使用平台 SQLite；Rust 提供既有備份鎖及 freezer。擷取與正式寫入共用完整 GMS UID 凍結、獨立監看程序、期限與 PID 身分核對；副本整理在凍結之外進行。

受保護操作目前有 30 秒監看期限。超大型資料庫的快照若超時，會中止並走既有復原流程，不發布不完整快照；這是限制 GMS 長時間凍結的取捨，不能解讀為保證所有資料庫都能在期限內備份。超時診斷與未完成的復原日誌必須保留。

寫入前在 /data/.speedbackup_timeline/ 保存回滾快照及持久日誌。失敗／程序中斷時嘗試回滾、解凍；未完成修復時不繼續，地圖恢復入口會先執行既有中斷修復。不要刪除待修復目錄。

恢復只改時間軸表，重新映射 Geller data ID，交易內驗證其他 Google 資料不變；保持 journal 模式，修正 SQLite sidecar 的 UID、模式與 SELinux 標籤。完成後停止舊 Maps／GMS 程序清除快取。

- 同帳號：已由 CPH2747 備份至 Xiaomi 13，29,481 筆行程；使用者確認地點與路線正常。
- 不同帳號研究：Xiaomi 13 的 29,481 筆行程及 300 筆編輯紀錄成功轉到另一帳號；原時間與內容比對一致，重啟及 30 秒後紀錄保留，使用者確認新帳號完整顯示歷史地點與路線。
- 支援已驗證的 ODLH 12、aux 1、Geller 9 結構；平台 SQLite 需支援 VACUUM INTO，並能使用現有 cgroup freezer。
- v814 備用機同份歷史依序匯入 A、B、A：兩帳號各 29,522 筆行程、300 筆編輯，逐筆內容相同，另一帳號完整列不變。刻意核驗失敗及寫入中途 SIGKILL 後皆回滾成功，兩帳號完整列與事前一致。這些資料庫結果不等同地圖畫面或雲端驗證。
- 官方 Google 雲端備份／重新匯入、長期同步、所有 GMS 版本及真正斷電未全面驗證；本機短期成功不代表全部通過。

## 選單歡迎詞

有 GMS 且本機可讀到 Google 帳號名稱時顯示歡迎詞；多帳號顯示已登入名稱，不猜目前使用中的帳號。每次啟動只向既有 daemon 查詢一次，選單重繪用 Shell 快取，讀取逾時或失敗即略過。名稱來自本機快取，可能與剛在線上修改的名稱暫時不同。

歡迎詞只寫互動終端，略過 debug 記錄及重導向 stdout；無互動終端／背景模式不顯示。Dex 的 TIMELINE 診斷由 Shell 收至 stderr debug，終端只保留使用者提示。

v815 起，歡迎詞與 Timeline 共用 `/data/.speedbackup_account_names` 的帳號顯示快取（root、0700；JSON 為 0600），僅保存姓名、必要帳號識別與失效判斷資料，不保存信箱、密碼或權杖。保留既有姓名格式及多帳號顯示。

快取按 Android 使用者分開，核對主資料庫、WAL、rollback journal 的存在狀態、inode、大小與修改時間，最長 24 小時重新整理。快取有效時只檢查檔案屬性，不讀取資料庫內容。恢復及備份的帳號綁定核對強制重新讀取，不以顯示快取授權寫入。

重新讀取時，僅以普通檔案讀取將 accounts_ce.db 及存在的 WAL 複製到 root 私有目錄，SQLite 只開副本，不對系統帳號資料庫建立 SQLite 連線或修正其附屬檔。複製前後核對屬性與內容雜湊，副本通過 quick_check 後才取用；發現來源變動或非空 rollback journal 即拒絕，不退回過期快取。這不是鎖定中的原子備份，不能保證消除所有併發競態。SQLite 官方也提醒活動資料庫直接複製可能不一致：https://www.sqlite.org/howtocorrupt.html 。

正常完成及例外路徑都刪除私有副本；若程序遭 SIGKILL 或斷電，finally 無法執行，可能留下僅 root 可讀的副本。副本短暫含完整帳號資料庫，不應放入日誌、交付包或一般備份。歡迎詞仍保持失敗即略過；Timeline 無法確認帳號時拒絕繼續。
