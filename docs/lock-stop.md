# v804 重複啟動的受限停止選單

已有備份鎖時，start.sh 不再直接拒絕退出，而是只提供 15（強制殺死運行中腳本）及 0（退出，保留原工作）。其他備份／恢復功能不可進入。選 15 成功後退出，使用者重新執行 start.sh 才回到正常選單。

Shell 記錄顯示選單時的 owner token，Rust lock-stop 在持有 guard flock 時核對 token、PID、/proc 啟動時間及 boot ID。token 變更、程序身分不符、guard 忙碌、pidfd 不可用時拒絕；不以全域 killall 或刪鎖冒充停止。不得停止控制程序本身或其祖先。

Rust 以 pidfd 固定程序身分，暫停擁有者與仍屬其後代的程序，掃描至穩定，再由子程序至擁有者發送 SIGKILL。確認所有已捕捉程序退出後才移除 owner、pid 及鎖目錄；掃描失敗會恢復本次暫停的程序，失敗不強行清鎖。已在掃描前脫離／重新掛到其他父程序的 daemon 不屬此程序樹。

強制停止會跳過原腳本 EXIT 收尾，當前備份或恢復可能不完整。此選項不表示資料操作已成功，也不會發送電腦關機命令。鎖身分無法確認時需保留診斷，不開放不驗證的強制刪鎖。

驗證：備用機 Android mksh + 本次交付 Rust；10 組隔離情境通過。使用實際 lock-acquire、lock-stop、lock-release、受限選單及 kill_Serve 鎖失敗分支（僅將鎖路徑映射到測試目錄）。忽略 TERM 的腳本及兩層子程序確實停止，旁邊的控制程序存活；選 0、非法選項、錯 token、自身／祖先、換人、guard 競爭、重複停止及 stale lock 回收通過。未終止手機原本的正式腳本，未做完整 start.sh 初始化流程的端到端操作。

退出碼：0 已核實停止並清除鎖；1 身分／鎖競爭／清理失敗或結果未完成；2 參數錯誤；3 核心沒有可用 pidfd（ENOSYS），保留擁有者與鎖，不降級成無身分檢查的 kill。
